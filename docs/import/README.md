# Імпорт прайсів і профілі постачальників

Цей документ для того, хто підключає магазин або нового постачальника:
розробника чи працівника магазину, який не боїться відкрити JSON-файл.
Щоденна робота власника (завантажити свіжий прайс, відповісти на звіт)
відбувається в Telegram і описана в кінці.

## Навіщо це потрібно, якщо є Auto-DB

Бот бере дані з двох джерел, і кожне знає своє:

| Що | Звідки |
|---|---|
| Які марки, моделі й двигуни існують | Auto-DB, для марок, яких там немає (Chery, BYD, JAC), — `data/vehicles.csv` |
| Які деталі виробників існують для машини | Auto-DB (обхід машини) |
| **Що лежить на полиці магазину, скільки і за скільки** | **прайс магазину чи постачальника, через імпорт** |
| Фото, номери виробника авто, аналоги | Auto-DB, якщо товар у ньому знайшовся; інакше прайс |

Auto-DB — це каталог, а не склад: у ньому немає ні цін магазину, ні
залишків. Тому без імпорту бот може запропонувати лише деталі «під
замовлення» з ціною, яку менеджер називає вручну. Імпорт наповнює
«✅ в наявності»: товари з ціною й залишком, які можна покласти в кошик
одразу.

## Як працює імпорт

```
файл (.xlsx / .csv)
  → профіль: які колонки що означають
  → розбір рядків: назва, ціна, залишок, артикул, бренд, авто
  → категорія: правила профілю, потім ключові слова data/categories.csv
  → бренд: одне написання на бренд ("KYB", "Kyb", "K.Y.B." — один)
  → авто: назви з прайсу → моделі довідника
  → звіт пробного прогону (нічого не змінено)
  → «Застосувати»: усе в одній транзакції
```

Що варто знати про поведінку:

- **Пробний прогін точний.** Він виконує імпорт повністю і відкочує
  транзакцію. Тож цифри у звіті — не оцінка, а те, що станеться.
- **Повторний імпорт оновлює, а не дублює.** Товар упізнається за
  `source` профілю і кодом постачальника (колонка `external_id`), а якщо
  коду немає — за брендом і артикулом. Ціни й залишки оновлюються на місці.
- **Зниклі з прайсу товари знімаються з продажу**, якщо в профілі
  `deactivate_missing: true`. Якщо так зникло б більше 20% товарів
  постачальника, імпорт зупиняється: обрізаний файл (один аркуш із шести)
  виглядає так само, як постачальник, що перестав продавати пів асортименту.
  Застосувати все одно можна, але лише окремою свідомою дією.
- **Залишок враховує відкриті замовлення.** Одиниці, утримані
  неоплаченими замовленнями, віднімаються від залишку з файлу.
- **Назву авто бот ніколи не вгадує.** Назва, якої немає в довіднику,
  потрапляє у звіт. Неправильна сумісність означає проданий товар, що не
  підходить.

## Профіль

Профіль — JSON-файл у теці `profiles/`, по одному на постачальника (або на
формат файлу). Ім'я файлу без `.json` — це назва профілю: її пишуть у
підписі до файлу в Telegram. У Docker тека підключена як том, тож новий
профіль не потребує перезбирання бота.

### Найменший робочий профіль

Для файлу, де є код товару, назва, ціна й залишок:

```json
{
  "source": "avtomir",
  "sku_prefix": "AM",
  "columns": {
    "external_id": "Код товару",
    "name": "Найменування товару",
    "price": "Ціна роздріб, грн",
    "stock": "Наявність"
  },
  "default_category": "other",
  "deactivate_missing": true
}
```

### Усі поля

| Поле | Обов'язкове | Що означає |
|---|---|---|
| `source` | так | Ідентифікатор постачальника: малі латинські літери, цифри, дефіс. **Після першого імпорту не змінювати**: за ним повторний імпорт знаходить свої товари. Нове значення означає нового постачальника, і старі товари стануть дублями. |
| `sku_prefix` | так | Початок внутрішнього коду товару: `AM` дає `AM-7KQ2M9XW4P`. |
| `columns` | так | Назви колонок у файлі, див. нижче. |
| `default_category` | так | Категорія для рядків, які не впізнало жодне правило і жодне ключове слово. Має бути категорією без підкатегорій (зазвичай `other`). |
| `lead_time_days` | якщо немає `stock` | Файл без залишків — це прайс постачальника, а не полиця магазину: усі товари стають «під замовлення, N днів». |
| `markup_percent` | ні | Націнка до закупівельної ціни: `25` робить 1000 грн у файлі 1250 грн у боті. |
| `deactivate_missing` | ні | `true` для повного прайсу: зниклі товари знімаються з продажу. Для часткового файлу (лише нові надходження) — `false`. |
| `max_deactivate_percent` | ні | Поріг захисту від обрізаного файлу, за замовчуванням `20`. |
| `csv_delimiter` | ні | Роздільник CSV. Якщо порожньо, визначається сам (`;`, `,`, табуляція, `\|`). Кодування Windows-1251 теж розпізнається саме. |
| `rules` | ні | Правила категорій саме для цього постачальника (див. нижче). |
| `vehicles` | ні | Відповідність назв авто з файлу моделям довідника (див. нижче). |
| `create_categories` | ні | Категорії, які треба створити, якщо їх немає: `{"slug": "Назва"}`. |

### Колонки

Колонку шукають за текстом заголовка, без урахування регістру й зайвих
пробілів, у будь-якому порядку, під будь-якою «шапкою» над таблицею, на
будь-якому аркуші. Аркуші без потрібного заголовка (обкладинка, примітки)
пропускаються.

| Ключ | Обов'язковий | Вміст |
|---|---|---|
| `name` | так | Назва товару. |
| `price` | так | Ціна в гривнях: `1049`, `1 049,50`, `1049 грн`, `1,049.50`. |
| `external_id` | одне з двох | Код товару в обліку постачальника. Найкращий ключ для повторного імпорту. |
| `part_number` | одне з двох | Артикул. Без `external_id` ключем стає бренд + артикул. Артикул також потрібен, щоб товар знайшовся в Auto-DB і за номером у пошуку. |
| `brand` | ні | Бренд. |
| `stock` | ні | Залишок: `5`, `5.0`, `>10`, `10+`. Порожньо означає 0. |
| `category` | ні | Група постачальника. Не стає категорією напряму, але допомагає правилам і ключовим словам. |
| `vehicle` | ні | Авто: `Chery Tiggo 7` або кілька через кому чи `;`. |
| `years` | ні | Роки однією колонкою: `2013-2020`, `2017-`, `2013–н.в.`. Або дві: `year_from` і `year_to`. |
| `position` | ні | Де на авто: «передня вісь», «ліва». Показується на картці. |
| `note` | ні | Примітка до сумісності: «з ABS». |
| `description` | ні | Опис. |
| `image` | ні | Посилання на фото. |

### Правила категорій (`rules`)

Здебільшого правила не потрібні. Дерево категорій
(`data/categories.csv`) має ключові слова українською й російською, і на
реальному прайсі 81 тис. рядків без жодного правила профілю нерозпізнаними
лишилося 2,6%. Ці назви власник досортовує сам командою `/word`.

Правило потрібне, коли постачальник має власну особливість: «усе з групи
"Щітки" — універсальне», «рядки з "ремкомплект" у цього постачальника — це
супорти»:

```json
"rules": [
  { "contains": ["щітка склоочисника"], "category": "mirrors-glass", "universal": true },
  { "contains": ["масло моторне"], "category": "engine-oil", "part_type": "engine_oil" }
]
```

Правила перевіряються по черзі, і спрацьовує перше, чиє слово є в назві
або групі постачальника. Правило має перевагу над ключовими словами дерева.
`universal: true` означає, що деталь підходить до будь-якого авто (масла,
лампи). `part_type` — це роль деталі в комплекті ТО: `engine_oil`,
`oil_filter`, `air_filter`, `cabin_filter`, `spark_plug`.

### Назви авто (`vehicles`)

Назва авто з файлу знаходить модель довідника сама, якщо збігається
«Марка Модель» (`Chery Tiggo 7`, `chery tiggo-7` — те саме) або лише модель
однієї марки. Решта потрапляє у звіт як «невідомі авто».

Їх простіше зіставити в Telegram: кнопка «🚗 Зіставити авто» під звітом,
ШІ пропонує, власник підтверджує. Профіль для цього потрібен лише тоді,
коли відповідність має бути частиною налаштування, наприклад для нового
магазину з тим самим постачальником:

```json
"vehicles": {
  "Chevrolet Aveo": ["Chevrolet Aveo T200", "Chevrolet Aveo T250"],
  "VW Golf VII": ["Volkswagen Golf VII"]
}
```

Праворуч мають бути моделі, які вже є в довіднику. Інакше профіль не
пройде перевірку, і помилка назве модель, якої бракує. Відповідність із
профілю має перевагу над підтвердженою в чаті.

## Підключення нового постачальника, крок за кроком

1. **Отримайте справжній файл** від постачальника, такий, який він
   надсилатиме регулярно.
2. **Знайдіть рядок заголовків** і випишіть, як точно називаються колонки.
3. **Напишіть профіль** у `profiles/<назва>.json`. Почніть із найменшого
   прикладу вище й додайте ті колонки, які є.
4. **Пробний прогін.** У Telegram надішліть файл у чат менеджерів із назвою
   профілю в підписі. З командного рядка:
   ```bash
   make import PROFILE=profiles/<назва>.json FILE=прайс.xlsx DRY_RUN=1
   ```
5. **Прочитайте звіт** (див. нижче) і виправте профіль, якщо треба.
   Повторюйте пробний прогін, доки звіт не стане чистим.
6. **Застосуйте**: кнопка «Застосувати» в чаті, або та сама команда без
   `DRY_RUN=1`.

Якщо магазин ще не має довідника авто, спочатку завантажте його:
`make import-vehicles`, або файл `data/vehicles.csv` у чат із підписом
`авто`. Сумісності прайсу можуть посилатися лише на моделі, які довідник
знає.

## Як читати звіт

| Розділ звіту | Що означає | Що робити |
|---|---|---|
| Не прочитано рядків, з номером рядка | Немає назви, ціни, коду; незрозуміла ціна чи роки | Подивитися рядок у Excel. Якщо таких багато, найімовірніше, колонку в профілі вказано неправильно. |
| Нові бренди | Бренди, яких бот ще не бачив | Переконатися, що це не помилка в написанні. Написання, що відрізняються лише розділовими знаками («K.Y.B.»), бот об'єднує сам. Інше («Kayaba» для KYB) поки що додається як синонім одним SQL-запитом у `brand_aliases`, команди в чаті для цього ще немає. |
| Невідомі авто | Назви, які не знайшли модель | «🚗 Зіставити авто» в чаті, або `vehicles` у профілі, або «➕ Додати в довідник», якщо такої машини в довіднику немає. |
| Нерозпізнані назви | Товари, що пішли в `default_category` | `/word <слово>` у чаті менеджерів. |
| Без сумісності | Товари без жодного авто й не універсальні | Нормально для прайсу без колонки авто: такі товари знайдуться пошуком, але не у фільтрі «для мого авто». |
| Знімається з продажу N | Товари, яких більше немає у файлі | Якщо цифра неочікувано велика, перевірте, чи файл повний. |

Помилка «немає колонок» називає відсутні колонки й показує найбільш схожий
рядок файлу. Зазвичай у ньому одразу видно, як колонку перейменували.

## Регулярне оновлення

Власник надсилає свіжий файл у чат менеджерів із тим самим підписом, читає
звіт і натискає «Застосувати». Профіль змінювати не треба, доки
постачальник не змінить формат файлу. Якщо змінить, бот скаже, якої
колонки бракує.

Після імпорту фоновий процес шукає кожен товар з артикулом в Auto-DB і
додає фото, номери виробників авто й аналоги. Тут грає роль якість прайсу.
Товар, записаний артикулом бренду (MANN `W 712/95`, Bosch
`0 986 479 C93`), знаходиться. Товар, записаний номером виробника авто
(Chery `T11-1117110`), — ні: пошук Auto-DB шукає лише за артикулами
брендів. Тому, якщо постачальник може дати колонку з артикулом бренду, її
варто вказати як `part_number`.

## Довідник авто (`data/vehicles.csv`)

Власний довідник магазину. З Auto-DB він потрібен для двох речей:

- **Марки, яких немає в Auto-DB** (Chery, BYD, JAC, Haval). Покупець
  такого авто обирає його з довідника магазину.
- **Сумісності з прайсу.** Прайс каже «Chevrolet Lacetti», а Auto-DB
  називає машину «Lacetti (J200)». Машина з Auto-DB прив'язується до
  моделі довідника, і сумісності прайсу доходять до неї.

Нову машину можна додати в чаті: `/car Peugeot 308 T7 2008-2013 1.6 HDi
дизель`, або з кнопки під звітом.

## Файли в репозиторії

- `profiles/demo-stock.json` + `docs/import/example-price.csv` — робочий
  приклад, його ж імпортує інтеграційний тест.
- `profiles/avtomir.json` + `docs/import/avtomir-demo.xlsx` — приклад
  іншого формату: Excel, інші назви колонок, роки однією колонкою.
- Профілі й прайси справжніх постачальників у репозиторій не кладуть:
  це комерційні дані магазину.
